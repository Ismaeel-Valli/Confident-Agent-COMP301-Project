# Project statistics (data dictionary)

Generated by `EvaluateBenchmark/compile_stats.py` from the evaluator's results
(`results/<label>/per_task.jsonl`), the benchmark's per-task result files (run folders
or the zipped archives in `Benchmark/`), the run manifests and the dataset. Rerun after
every new benchmark run and evaluation:

```bat
cd EvaluateBenchmark
python evaluate_benchmark.py
python compile_stats.py
```

Conventions: `b_` = baseline, `i_` = intervention (Confident Agent). Rates are shares
from 0 to 1. Empty cells mean "not recorded" (for example energy in run 1, which had no
power measurement) or "undetermined". Classes follow `Benchmark/EVALUATION_PLAN.md` §2:
`correct`, `A` (API hallucination), `B` (valid call, wrong for the task),
`runtime_failure`, `undetermined`, `no_code`; for the intervention also `nothing_shown`
(withheld). Summaries (`group_stats`, `model_comparison`, `verifier_detection`,
`error_kinds`) exclude the 10 pilot tasks (plan §6); `prompt_stats` has all.

## prompt_stats.csv: one row per prompt and run

**Run.** `model_label` (one run, e.g. a quantization), `model`, `quantization`,
`architecture`, `context_length`, `thinking`, `temperature`, `benchmark_version`,
`machine_gpu`, `machine_cpu`.

**Prompt.** `task_id`, `api`, `operation_category` (read, create, update, delete,
search_filter), `http_method`, `endpoint`, `difficulty` (the dataset's heuristic),
`auth_type` (none, bearer, api_key, oauth2), `spec_source` (official provider
specification or documentation-derived partial one), `operation_family` (related prompts
share one), `pilot` (1 = development task), `instruction_chars`.

**Baseline.** `b_class`; `b_hallucination` (1 = class A, empty = undetermined);
`b_correct`; `b_hallucination_kinds` (class A), `b_task_error_kinds` (class B) and
`b_runtime_failure_kind` (see error_kinds.csv); `b_reasons` (the evaluator's findings); `b_has_code`; `b_finish_reason`; behaviour checks
`b_returns_expected`, `b_empty_response_ok`, `b_error_raises`.

**Intervention.** `i_decision` (the verifier's final decision), `i_delivered`,
`i_withheld` (abstained), `i_ewcs`, `i_first_decision`, `i_first_ewcs`, `i_code_shown`,
`i_unapproved_code_shown` (code in the reply that the tool did not approve),
`i_shown_class` (what reached the user), `i_hallucination_reaches_user`,
`i_correct_reaches_user`, `i_hallucination_kinds`, `i_task_error_kinds`,
`i_runtime_failure_kind`, `i_shown_reasons`, `i_final_class`
and `i_first_class` (the last and first verified candidates, shown or not),
`i_verification_calls`, `i_tool_failures`, `i_model_turns`, `i_first_had_contradiction`,
`i_correction_attempted`, `i_correction_allowed`, `i_correction_count`,
`i_correction_outcome` (first class -> final class), `i_final_reply_prompted`,
`i_reply_matches_report`, `i_protocol_note_count`, `i_protocol_notes`, and the behaviour
checks as for the baseline.

**Cost, per mode** (`b_` and `i_`): `_duration_s` (wall clock for the prompt),
`_model_s` and `_tool_s` (time in LM Studio and in verification; from run 2),
`_model_requests`, `_prompt_tokens`, `_completion_tokens`, `_total_tokens`,
`_completion_tokens_per_s`, `_gpu_energy_j`, `_cpu_energy_j`, `_energy_j` (sum of the
measured channels), `_energy_wh`, `_energy_above_idle_j`, `_energy_source`
(nvidia-smi or LibreHardwareMonitor), `_started`, `_error`.

**Paired.** `pair_hallucination`: `repair` (baseline hallucinated, intervention did
not), `regression` (the reverse), `both`, `neither`. `pair_correct`: `repair`
(intervention delivered correct code, baseline did not), `regression` (baseline was
correct, intervention was not, including correct code withheld), `both`, `neither`.
`verifier_outcome`: the verifier as a detector of a hallucinated final candidate, TP
(hallucination withheld), FN (hallucination delivered), FP (non-hallucination withheld),
TN (non-hallucination delivered). `time_ratio`, `energy_ratio` (intervention / baseline)
and `extra_tokens` (intervention - baseline).

## group_stats.csv: per run and group

`dimension` is `overall`, `api`, `operation_category`, `http_method`, `difficulty`,
`auth_type` or `spec_source`; `group` is its value; `n` prompts.

- `b_/i_hallucination_rate` (with Wilson 95% interval `_ci`), over decided prompts.
- `hallucination_paired_n`, `_repairs`, `_regressions`, `_both`, `_neither`,
  `_improvement` ((repairs - regressions) / paired n; positive = the intervention is
  better) and `_mcnemar_p` (exact). The same for `correct_...`. Subgroup p-values are
  descriptive (no correction for the number of groups).
- `b_/i_B_count`, `_runtime_failure_count`, `_undetermined_count`.
- `i_abstention_rate`, `i_incorrect_acceptance` (hallucination shown), `i_incorrect_rejection`
  (correct final candidate withheld), `i_unapproved_code_shown`, `i_mean_ewcs`,
  `i_mean_verification_calls`, `i_tool_failures`, `i_corrections_attempted`,
  `i_correction_success_rate` (final candidate correct), `i_final_reply_prompted_rate`,
  `i_protocol_compliance_rate` (no protocol notes).
- `b_/i_behaviour_all_ok_rate`: all three behaviour checks met.
- Cost: `_mean_duration_s`, `_median_duration_s`, `_total_duration_h`, `_mean_total_tokens`,
  `_mean_energy_j`, `_total_energy_wh`, and efficiency `_seconds_per_correct_answer`,
  `_wh_per_correct_answer` (total cost / prompts with correct code reaching the user).

## model_comparison.csv: one row per run

The run's settings and machine, the `overall` figures of group_stats, and
`hallucination_mcnemar_p_holm` (Holm-adjusted across runs, plan §6). This is the table
for comparing quantizations and models.

## verifier_detection.csv

The verifier judged as a detector (positive = the final candidate is wrong; predicted
positive = withheld), overall and per API, for two targets: `A` (hallucination) and
`A_or_B` (hallucination or wrong for the task). `TP`, `FP`, `FN`, `TN`, `precision`,
`recall`, `f1`, `false_positive_rate` (correct work withheld), `false_negative_rate`
(wrong work delivered), `specificity`, `accuracy`. Undetermined candidates are left out.

## error_kinds.csv

Kinds of error in the code reaching the user, per run, mode (`baseline`,
`intervention`), `error_class` and category (`dimension` and `group` as in
group_stats). `tasks` prompts with the kind, `group_tasks` prompts in the group,
`share_of_group`. A prompt can have several kinds of class A or B.

| error_class | Kinds |
|---|---|
| `A` (API hallucination; project description appendix A.2) | wrong host, version or base path; invented endpoint or method; invented parameter or body field; invalid value or structure; missing required part or credential; undocumented response field; non-existent requests API |
| `B` (valid call, not the task's) | different declared endpoint; method not acceptable for the task; omitted parameter the task specifies; different parameter value; omitted request body; unrequested request body; request body differs (fields or values); extra requests; credential missing or malformed (API requirement unknown); JSON body sent as form data; insecure scheme (http) |
| `runtime_failure` (no request made) | input used as the wrong type (e.g. credential string as a dict); reads an input the task does not provide; syntax error; makes no request; does not finish (timeout); blocked operation; undefined name; raises its own error before the request; wrong call or argument types |

Anything not matched is `other`. The kinds are read from the evaluator's findings with
fixed rules (`evaluate_benchmark.py`: `HALLUCINATION_TYPES`, `TASK_ERROR_TYPES`,
`RUNTIME_FAILURE_TYPES`).

## Notes

- The primary result of the project (with bootstrap intervals over tasks and operation
  families) is in `results/report.md`; these tables are its descriptive companion. Rates
  here are per mode over decided prompts, so they can differ slightly from the report's
  paired primary row, which drops a prompt when either mode is undetermined.
- Run 1 has no power measurement, and no model or tool time split.
